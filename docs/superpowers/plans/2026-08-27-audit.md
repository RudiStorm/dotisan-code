# Audit Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close out the authorization slice as v0.3.0 and add the v0.4 audit foundation to plain and authenticated generated applications.

**Architecture:** Version metadata is updated first. Audit remains application-owned generated C# using standard ASP.NET Core dependency injection, configuration, Minimal APIs, EF Core, Identity, and `System.Text.Json`. A scoped generated `IAuditWriter` persists explicit audit records; generated authentication and resource endpoints call it directly, while arbitrary user endpoints remain opt-in.

**Tech Stack:** .NET 8, ASP.NET Core Minimal APIs, EF Core SQLite, ASP.NET Core Identity, `IConfiguration`, `IServiceCollection`, `HttpContext`, `System.Diagnostics.Activity`, `System.Text.Json`, xUnit, `WebApplicationFactory`, Vue/Vite, existing Dotisan generator and CLI projects.

**Spec:** `docs/superpowers/specs/2026-08-27-audit-design.md`

## Global Constraints

- Generated applications remain ordinary ASP.NET Core applications using standard dependency injection, configuration, Minimal APIs, EF Core, and Identity.
- Generated audit source is written into the application and remains directly editable.
- Endpoint and audit behavior is explicit in generated C#; there is no hidden runtime discovery.
- EF Core remains the persistence boundary and `dotnet ef` remains the migration-authoring tool.
- Audit records are not silently discarded when enabled and persistence fails.
- Existing plain/authenticated source boundaries remain intact except for the shared audit infrastructure.
- Auditing is generated and enabled by default for both plain and authenticated projects.
- The runtime setting is `Audit:Enabled` with generated default `true`; `Audit__Enabled=false` is the documented standard override.
- Tenant ID is nullable and remains null until the tenancy roadmap slice supplies tenant resolution.
- No generated migration, audit query API, admin UI, event sourcing, background job, OpenTelemetry setup, external provider, custom persistence abstraction, or reflection discovery is added.

- `src/Dotisan.Generators/TemplateFiles.cs`: generated package version, audit model/writer/configuration/program registration, auth audit calls, generated integration tests, and generated README.
- `src/Dotisan.Generators/GoldenTemplateGenerator.cs`: explicit audit calls emitted by authenticated resource scaffolding and configuration-independent source generation.
- `tests/Dotisan.Cli.Tests/CliApplicationTests.cs`: v0.3.0 CLI version assertion.
- `tests/Dotisan.Generators.Tests/GoldenTemplateGeneratorTests.cs`: generated audit source, configuration, security tests, and resource audit assertions.
- `tests/Dotisan.Core.Tests/`: unchanged unless a small shared contract assertion is required; audit is intentionally application-local rather than a Dotisan.Core abstraction.
- `README.md` and `docs/quickstart.md`: v0.3.0 release alignment, audit workflow, configuration, migration, and scope documentation.
