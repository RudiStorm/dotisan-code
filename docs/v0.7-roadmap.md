# Dotisan v0.7 Roadmap

v0.7 is focused on production readiness after the v0.6 contract, authentication, audit, and jobs foundations.

## Baseline

- Keep generated applications as ordinary ASP.NET Core + Vue applications.
- Make `dotisan doctor --production` provide actionable, read-only readiness checks.
- Test generated plain and authenticated projects in CI, including API builds, migrations, and frontend checks.
- Keep development initialization convenient while requiring reviewed, committed migrations in production.
- Keep documentation aligned with the actual CLI and generated template behavior.

## Follow-up slices

### Multi-tenancy

Add tenant resolution, tenant context, EF isolation, tenant-aware writes, and cross-tenant integration tests. `--tenant no` must preserve the current generated shape.

### Observability

Add standard OpenTelemetry traces and metrics, configurable OTLP/Aspire development export, and documented correlation behavior without hard-coding a production vendor.

### Authentication completion

Add email confirmation, password reset, TOTP MFA, recovery codes, session management, and explicit SMTP/Mailpit and external-provider extension points using standard ASP.NET Identity.

### Application integrations

Add separately specified slices for notifications, storage, caching, imports/exports, webhooks, and SignalR updates. Each integration must generate ordinary source and configuration rather than an opaque runtime plugin.

## Acceptance criteria

The v0.7 release is ready when a generated application can pass `dotisan doctor --production`, its API and frontend checks run in CI, tenant isolation and authentication security behavior have integration coverage, and all user-facing documentation describes the shipped behavior accurately.
