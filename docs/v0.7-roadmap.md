# Dotisan v0.7 Roadmap

v0.7 is focused on production readiness after the v0.6 contract, authentication, audit, and jobs foundations.

## Baseline

- Keep generated applications as ordinary ASP.NET Core + Vue applications.
- Make `dotisan doctor --production` provide actionable, read-only readiness checks.
- Test generated plain and authenticated projects in CI, including API builds, migrations, and frontend checks.
- Keep development initialization convenient while requiring reviewed, committed migrations in production.
- Keep documentation aligned with the actual CLI and generated template behavior.

## Completed v0.7 foundation slices

### Multi-tenancy

Tenant resolution, tenant-aware writes, generated CRUD predicates, and development/header versus production/claim boundary tests are implemented. `--tenant no` preserves the non-tenant generated shape. Domain-specific cross-tenant scenarios should be added alongside each resource created with `dotisan make:resource`.

### Observability

Standard OpenTelemetry traces, metrics, EF Core and logging instrumentation, configurable OTLP/Aspire development export, and correlation guidance are implemented without selecting a production vendor.

### Authentication completion

Email confirmation, password reset, TOTP MFA, recovery codes, session management, and explicit SMTP/Mailpit and external-provider extension points are implemented using standard ASP.NET Identity.

### Application integrations

Notifications, storage, caching, imports/exports, webhooks, and SignalR remain deferred follow-up slices. Each future integration must generate ordinary source and configuration rather than an opaque runtime plugin.

## Acceptance criteria

The v0.7 foundation is ready when a generated application can pass `dotisan doctor --production`, its API and frontend checks run in CI, generated tenant/authentication boundary coverage passes, and all user-facing documentation describes the shipped behavior accurately. A v0.7 package/version bump is a separate release-closeout decision.
